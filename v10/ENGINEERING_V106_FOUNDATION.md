# V106 Engineering Foundation

## الهدف
إعادة تأسيس قلب محرك التوثيق دون تغيير تجربة المستخدم الحالية أو حذف منطق تربوي صحيح. V106 تفصل بين الفهم، حالة الوثيقة، اختيار السؤال، والتوليد، بحيث تقرأ جميع المخرجات من سياق واحد.

## ما نُفذ
1. `canonical-context106.js`: مصدر سياق موحد مع provenance لكل حقيقة: user / classification / inference / resolver / unknown.
2. `skill-resolver106.js`: فصل الموضوع عن المهارة مع أولوية العبارة الدقيقة على التطابق الأوسع.
3. `question-router106.js`: اختيار سؤال واحد في كل دورة وفق أكبر فجوة متبقية، مع قياس شرطي عند ادعاء نتيجة.
4. `matrix106.js`: نقطة دخول موحدة للمصفوفة + المهارة + السؤال التالي.
5. `generators106.js`: عنوان وأهداف ونص تجريبي كلها تقرأ من Canonical Context نفسه ولا تعيد تحليل النص.
6. `document-repository106.js`: فصل drafts / documents / attachments وإعطاء الوثيقة معرفًا مستقلًا.
7. `engineering106-tests.js`: اختبارات الحالة والسياق والمهارة والـRouter والمولدات وعدم اختراع القياس.
8. GitHub Actions gate: تشغيل اختبارات V106 مع اختبارات V85 السابقة ومنع استخدام sessionStorage داخل قلب V106 الجديد.

## قواعد غير قابلة للكسر
- الموضوع لا يساوي المهارة الدقيقة.
- اختيار المستخدم يتقدم على الاستنتاج.
- لا يعاد تحليل النص داخل مولد العنوان أو الأهداف أو الوصف.
- لا يظهر سؤال معروف الجواب.
- القياس لا يظهر إلا عند وجود نتيجة/أثر يحتاج إثباتًا أو في وثيقة تتطلبه منطقيًا.
- لا تتحول نتيجة غير مقاسة إلى حقيقة في النص.
- قلب V106 لا يستخدم sessionStorage.
- كل صفحة مستقبلًا لها Renderer واحد ومالك واحد.

## ما لم يُدمج بعد في واجهة V105
هذه المرحلة Foundation آمنة على فرع مستقل. لم تُستبدل بعد كل صفحات V105 بالـStore والـRouter الجديدين؛ الدمج المباشر قبل نجاح الاختبارات كان سيعرض النسخة الحالية للانكسار. بعد نجاح CI يتم دمج الطبقات تدريجيًا: الصفحة الثانية أولًا، ثم الأهداف والعنوان والنص، ثم الأرشيف.

## ترتيب الدمج
1. تحويل صفحة التفاصيل إلى سؤال واحد ثم إعادة حساب السؤال التالي بعد الإجابة.
2. نقل اختيار المادة من sessionStorage إلى DocumentState.
3. ربط goal/title/narrative بالمولدات الموحدة أو Context API.
4. إلغاء MutationObservers التي تعيد كتابة صفحات يملكها Renderer آخر.
5. تحويل الحفظ من `current` فقط إلى Document Repository.
6. إضافة tests للمؤشرات والشواهد والواجهة قبل اعتماد main.
